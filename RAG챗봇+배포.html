사용자 질문 입력
      │

      │

비유로 이해하기

2. RAG란 무엇인가

2.1 왜 RAG가 필요한가?

일반 LLM의 두 가지 한계:

문제 설명 예시
지식 단절 (Knowledge Cutoff) 학습 데이터 이후의 내용은 모름 2026년 선거법 개정 내용
환각 (Hallucination) 모르는 내용을 그럴듯하게 지어냄 존재하지 않는 조항 번호 인용

RAG는 이 두 문제를 외부 문서 검색으로 해결합니다.

2.2 RAG 3단계

① 준비 단계 (최초 1회) ← 이미 완료!
   원본 문서 → 청크 분할 → 임베딩 → 벡터 DB 저장

② 검색 단계 (질문마다)
   사용자 질문 → 임베딩 → 벡터 DB에서 유사 청크 검색

③ 생성 단계 (질문마다)
   검색된 청크 + 질문 → LLM → 출처 포함 답변

💡 이미 chroma_election_db/ 폴더가 있다면 ①은 건너뛰고 ②③만 실행됩니다.
RAG챗봇_배포.py는 기존 DB를 읽기 전용으로 로드하므로 DB를 다시 만들지 않습니다.

2.3 임베딩(Embedding)이란?

텍스트를 숫자 벡터로 변환하는 기술입니다.

"선거 보도 공정성"  →  [0.12, -0.45, 0.78, ...]  (768개 숫자)
"선거 뉴스 균형"    →  [0.11, -0.43, 0.76, ...]  (비슷한 숫자!)
"오늘 날씨 맑음"    →  [-0.89, 0.23, -0.11, ...]  (완전히 다른 숫자)

의미가 비슷한 문장은 비슷한 벡터를 가지므로, 코사인 유사도로 관련성을 측정할 수 있습니다.

2.4 비대칭 임베딩 (이 챗봇의 핵심 기법)

같은 임베딩 모델이라도 역할에 따라 다른 task_type을 지정해야 합니다.

# DB 구축 시 (이미 완료): 문서는 retrieval_document로 임베딩
embed_text("선거 보도 기준...", task_type="retrieval_document")

# 챗봇 실행 시: 질문은 retrieval_query로 임베딩 ← 이 코드가 매번 실행됨
embed_text("선거 보도 기준이 뭔가요?", task_type="retrieval_query")

두 task_type이 서로 짝을 이루어야 검색 정확도가 높아집니다.

3. 이 챗봇의 기술 스택

3.1 구성 요소 설명

구성 요소 역할 왜 이걸 선택했나
Streamlit 웹 UI Python만으로 대화형 앱 구현, 설치 쉬움
Gemini Embedding 001 질문 → 벡터 변환 768차원 Matryoshka, 한국어 우수
Chroma DB 벡터 검색 (사전 구축) 로컬 파일 기반, 별도 서버 불필요
Gemini 2.5 Flash-Lite 답변 생성 빠르고 저렴, 한국어 품질 우수
Hugging Face Spaces 무료 배포 GitHub 연동, 무료 CPU 인스턴스 제공

3.2 챗봇 실행 시 데이터 흐름

사용자 질문
    │
    ▼
embed_query(query, task_type="retrieval_query")
    │  → 768차원 벡터
    ▼
collection.query(query_embeddings=[q_vec], n_results=5)
    │  → 가장 유사한 청크 5개 반환
    ▼
[문서 1] (페이지 23, 유사도=0.87) ...청크 내용...
[문서 2] (페이지 31, 유사도=0.82) ...청크 내용...
    │
    ▼
Gemini 2.5 Flash-Lite에게 전달
  "다음 문서만 참고해서 [페이지N] 출처 표기하며 답하라"
    │
    ▼
답변 텍스트 + 📚 참고 페이지: [23, 31]

4. 챗봇 코드 핵심 설명

4.1 기존 DB 로드

@st.cache_resource(show_spinner=False)
def get_collection():
    """
    사전 빌드된 Chroma 컬렉션을 로드합니다.
    이 함수는 DB를 새로 만들지 않습니다.
    """
    client = chromadb.PersistentClient(path=DB_PATH)  # DB_PATH = "./chroma_election_db"
    col = client.get_collection(COLLECTION_NAME)       # 컬렉션을 읽기 전용으로 열기
    return col

왜 @st.cache_resource를 쓰나요?
Streamlit은 사용자가 입력할 때마다 스크립트 전체를 재실행합니다.
@st.cache_resource가 없으면 매번 DB를 다시 열게 됩니다.
이 데코레이터를 붙이면 최초 1회만 로드하고 이후에는 캐시에서 즉시 반환합니다.

4.2 질문 임베딩

def embed_query(text: str) -> list[float]:
    result = genai.embed_content(
        model=EMBED_MODEL,           # "gemini-embedding-001"
        content=text,
        task_type="retrieval_query", # ← 질문 검색용 task_type
        output_dimensionality=EMBED_DIM  # 768
    )
    return result["embedding"]       # 768개 숫자 리스트 반환

DB 구축 시 문서는 retrieval_document로 임베딩되었으므로, 질문은 반드시 retrieval_query를 사용해야 검색 정확도가 높아집니다.

4.3 관련 청크 검색

def search(collection, query: str, top_k: int = TOP_K) -> list[dict]:
    q_vec = embed_query(query)

    results = collection.query(
        query_embeddings=[q_vec],
        n_results=top_k,
        include=["documents", "metadatas", "distances"]
    )

    hits = []
    for doc, meta, dist in zip(
        results["documents"][0],
        results["metadatas"][0],
        results["distances"][0]
    ):
        hits.append({
            "text": doc,
            "page": meta.get("page", "?"),
            "score": round(1 - dist, 3)  # 코사인 거리 → 유사도로 변환
        })
    return hits

1 - dist를 쓰는 이유: Chroma는 거리(작을수록 유사)를 반환하므로 유사도(클수록 유사)로 변환합니다.

4.4 RAG 답변 생성

def generate_answer(collection, query: str, chat_history: list[dict]) -> str:
    hits = search(collection, query)   # ① 검색

    # ② 검색된 청크를 프롬프트용 텍스트로 조합
    context = "\n\n".join([
        f"[문서 {i}] (페이지 {h['page']}, 유사도={h['score']})\n{h['text']}"
        for i, h in enumerate(hits, 1)
    ])

    # ③ 시스템 프롬프트: 환각 방지 + 출처 표기 강제
    system_prompt = """아래 [검색된 문서]만 참고하여 질문에 답하세요.
각 주장 끝에 반드시 [페이지 N] 형식으로 출처를 표기하세요.
문서에 없는 내용은 '제공된 자료에서는 확인할 수 없습니다'라고 답하세요."""

    user_message = f"{system_prompt}\n\n[검색된 문서]\n{context}\n\n[질문]\n{query}"

    # ④ Gemini에게 대화 이력 포함해 전달
    model = genai.GenerativeModel(GEN_MODEL, generation_config={"temperature": 0.2})
    chat = model.start_chat(history=chat_history)
    response = chat.send_message(user_message)

    # ⑤ 참고 페이지 목록 추가
    source_pages = sorted({h["page"] for h in hits})
    return response.text + f"\n\n---\n📚 **참고 페이지:** {source_pages}"

4.5 session_state로 대화 이력 유지

# 두 종류의 이력을 별도로 관리합니다
st.session_state.messages       # Streamlit 화면 표시용
# [{"role": "user",      "content": "질문"}, ...]

st.session_state.gemini_history # Gemini API 전달용
# [{"role": "user",  "parts": "질문"},
#  {"role": "model", "parts": "답변"}, ...]  ← "model" (assistant 아님!)

Gemini API는 역할 이름으로 "assistant"가 아닌 "model"을 사용합니다. 혼동 주의!

6. Hugging Face Spaces 배포

Hugging Face Spaces는 무료로 AI 앱을 배포할 수 있는 플랫폼입니다.
GitHub처럼 파일을 올리면 자동으로 앱이 실행됩니다.

6.1 Hugging Face 계정 만들기

  1. huggingface.co 접속 → Sign Up
  2. 이메일 인증 완료

6.2 새 Space 만들기

  1. 로그인 후 우측 상단 프로필 → New Space 클릭
  2. 설정 입력:
항목 값
Space name election-rag-chatbot (원하는 이름)
License MIT
SDK Streamlit ← 반드시 선택!
Space hardware CPU basic · Free
Visibility Public 또는 Private
  1. Create Space 클릭

6.3 API 키 등록 (Secrets)

코드에 API 키를 직접 쓰면 절대 안 됩니다! Secrets를 사용하세요.

  1. Space 페이지 → Settings 탭
  2. Repository secrets 섹션 → New secret 클릭
  3. 입력:
    • Name: GEMINI_API_KEY
    • Value: AIza...본인키...
  4. Save 클릭

앱 코드에서 st.secrets["GEMINI_API_KEY"]로 자동으로 읽어옵니다.

7. 주요 설정값 조정 가이드

RAG챗봇_배포.py 상단의 설정값을 바꾸면 챗봇 동작을 튜닝할 수 있습니다.

7.1 기본 설정값

DB_PATH = "./chroma_election_db"   # 기존 DB 경로
COLLECTION_NAME = "election_guide" # DB 구축 시 사용한 컬렉션 이름과 동일해야 함
EMBED_MODEL = "gemini-embedding-001"
GEN_MODEL = "gemini-2.5-flash-lite"
EMBED_DIM = 768
TOP_K = 5

⚠️ COLLECTION_NAME은 DB 구축 시 사용한 이름과 반드시 일치해야 합니다.
다르면 "컬렉션을 열 수 없습니다" 오류가 발생합니다.

7.2 검색 설정

TOP_K = 5  # 검색할 청크 수
  • TOP_K = 3 → 빠르지만 컨텍스트가 적음
  • TOP_K = 5 → 균형 (기본값)
  • TOP_K = 8 → 풍부한 컨텍스트, 응답 시간 증가

7.3 생성 모델 temperature

generation_config={"temperature": 0.2}
temperature 적합한 상황
0.0~0.3 사실 기반 Q&A (이 챗봇처럼 정확성 중요한 경우)
0.5~0.7 일반적인 도우미
0.9~1.0 창의적 글쓰기, 브레인스토밍

8. 자주 묻는 질문

Q: "Chroma DB 폴더를 찾을 수 없습니다" 오류가 납니다.
A: chroma_election_db/ 폴더가 RAG챗봇_배포.py와 같은 위치에 있는지 확인하세요. 로컬이라면 경로를, Spaces라면 폴더가 커밋에 포함됐는지 확인하세요.

Q: "컬렉션을 열 수 없습니다" 오류가 납니다.
A: COLLECTION_NAME 값이 DB 구축 시 사용한 이름과 다릅니다. DB 구축 스크립트에서 사용한 컬렉션 이름을 확인해 RAG챗봇_배포.py의 COLLECTION_NAME과 맞추세요.

Q: "GEMINI_API_KEY를 찾을 수 없습니다" 오류가 납니다.
A: 로컬이면 .env 파일에 키가 있는지, Spaces라면 Settings → Secrets에 GEMINI_API_KEY가 등록됐는지 확인하세요.

Q: 이전 대화 내용을 기억하지 못합니다.
A: 브라우저 탭을 새로고침하면 session_state가 초기화됩니다. 같은 탭에서 계속 대화하면 이전 내용을 기억합니다.

Q: 답변이 "제공된 자료에서는 확인할 수 없습니다"라고만 합니다.
A: 질문이 원본 문서 범위 밖이거나 검색이 잘 안 된 경우입니다. 질문을 더 구체적으로 바꾸거나 TOP_K를 늘려보세요.

Q: Hugging Face Space가 자꾸 잠듭니다 (sleeping).
