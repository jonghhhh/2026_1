0. 강의 목표

이 강의는 비정형 데이터(문서·이미지)를 의미 단위로 분류하고, 각 묶음의 주제(theme)를 자동으로 도출하는 방법을 익히는 것이 목표다. 핵심 파이프라인은 다음과 같다.

원문 → (전처리/요약) → 임베딩 모델 → 벡터 → 클러스터링 → 클러스터별 대표 추출 → LLM 주제 도출

이 틀은 텍스트와 이미지에 동일하게 적용되며, 전통적인 LDA 토픽모델링이나 의미연결망 분석에 비해 의미 표현력·해석력·범용성 모두에서 우위가 있다.

1. 임베딩(Embedding)이란 무엇인가

1.1 직관적 정의

임베딩이란 단어·문장·이미지 같은 비정형 대상을 "고차원 공간 위의 한 점(벡터)"으로 변환하는 것이다.

비유하자면 도시를 "위도·경도"로 표현하는 것과 같다. "서울"이라는 이름만 듣고는 컴퓨터가 "부산"과의 관계를 알 수 없지만, (37.57, 126.98) ↔ (35.18, 129.07)로 표현하면 두 점 사이의 거리, 방향, 가까운 도시들을 계산할 수 있다. 임베딩은 이 "지도화" 작업을 의미 공간에 대해 수행하는 것이다.

좋은 임베딩이라면 다음이 성립해야 한다.

  • 의미가 비슷한 문서는 벡터 공간에서 가깝다
  • 의미가 다른 문서는 멀다
  • 벡터의 거리(또는 코사인 유사도)가 의미적 유사도와 대응한다

1.2 왜 임베딩이 필요한가: One-hot의 한계

전통적 표현 방식은 단어를 "사전 크기만큼의 벡터에서 해당 위치만 1, 나머지는 0"으로 표시했다(one-hot encoding). 이 방식은 두 가지 치명적 결함이 있다.

  1. 차원 폭발: 한국어 어휘만 수십만 단어, 문서 단위로 가면 더 커진다.
  2. 의미 표현 불가: "기자"와 "언론인"은 의미가 비슷하지만, one-hot에서는 완전히 직교한다. 컴퓨터는 두 단어가 무관하다고 판단한다.

TF-IDF 역시 본질적으로 단어 빈도 기반이라 의미가 아니라 표면 어휘의 일치만 잡아낸다. 같은 의미를 다른 단어로 표현하면 유사도가 0이 된다.

1.3 임베딩의 작동 원리: 분포 가설

현대 임베딩의 토대는 언어학자 J. R. Firth의 명제 — "단어의 의미는 그 주변에 함께 나타나는 단어들로 결정된다(You shall know a word by the company it keeps)" — 에 있다.

이를 분포 가설(distributional hypothesis)이라 한다.

  • "사과를 먹었다", "사과가 빨갛다", "사과나무" — '사과' 주변의 단어 분포를 학습하면, '사과'의 의미가 자연스럽게 좌표로 응축된다.
  • "배"도 비슷한 문맥에 자주 나타나므로 '사과'와 가까운 좌표에 위치한다.
  • '자동차'는 전혀 다른 문맥에 등장하므로 멀리 위치한다.

이 원리를 신경망으로 학습한 것이 Word2Vec(2013), GloVe(2014), FastText(2016) 등 초기 단어 임베딩이다.

1.4 단어 → 문맥 → 문장: 진화 단계

단계 모델 한계
정적 단어 임베딩 Word2Vec, GloVe, FastText "사과를 먹었다"의 '사과'와 "사과 회사 애플"의 '사과'가 같은 벡터. 다의어 처리 불가
문맥형 단어 임베딩 ELMo, BERT(2018), RoBERTa 같은 단어라도 문맥에 따라 다른 벡터. 하지만 문장 전체를 하나의 벡터로 만드는 데는 부적합(BERT의 [CLS] 토큰은 분류 학습에 최적화되어 있어 의미 유사도가 코사인 유사도와 일치하지 않음)
문장/문서 임베딩 SBERT(Sentence-BERT, 2019), SimCSE, E5, BGE 문장 단위 의미를 코사인 유사도가 잘 반영하도록 **대조 학습(contrastive learning)**으로 fine-tuning

1.5 SBERT(Sentence-BERT)의 원리

SBERT는 BERT를 Siamese network(같은 구조의 두 신경망을 쌍으로 연결한 모델) 구조로 fine-tuning한 모델이다.

  1. 두 문장 A, B를 같은 BERT에 통과시켜 각각 토큰 벡터를 얻는다.
  2. Mean pooling(토큰 벡터의 평균)으로 문장 벡터 u, v를 생성한다.
  3. 의미가 비슷한 쌍(예: NLI의 entailment, STS 데이터셋의 고점수 쌍)은 cos(u,v)가 1에 가깝게, 다른 쌍은 0에 가깝게 학습한다.

결과: 벡터 두 개를 코사인 유사도로 비교하기만 하면 의미 유사도를 알 수 있다. 이것이 BERT 대비 SBERT의 결정적 우위다. BERT로 두 문장의 유사도를 알려면 매번 두 문장을 함께 모델에 넣어야 했는데, SBERT는 각 문장을 한 번씩만 벡터화하면 그 다음은 단순 벡터 연산이다.

📐 코사인 유사도(Cosine Similarity)란?

두 벡터 u, v가 이루는 각도의 코사인 값으로 유사도를 측정한다. 벡터의 크기(길이)는 무시하고 방향만 비교하기 때문에, 짧은 문서와 긴 문서처럼 길이가 달라도 내용이 비슷하면 높은 유사도를 가진다.

cos(u, v) = (u · v) / (‖u‖ × ‖v‖)

기호 의미
u · v두 벡터의 내적(dot product) — 같은 위치 원소끼리 곱해서 다 더한 값
‖u‖벡터 u의 크기(L2 노름) — 각 원소²의 합에 루트를 씌운 값
cos(u,v) 결과−1 ~ +1 범위. +1 = 완전히 같은 방향(동일 의미), 0 = 직교(무관), −1 = 반대 방향

🎯 임베딩에서 핵심인 이유: SBERT는 의미가 비슷한 문장의 벡터가 같은 방향을 가리키도록 학습된다. 그래서 코사인 유사도만 계산하면 "이 두 기사가 얼마나 같은 주제를 다루는가"를 숫자 하나로 얻을 수 있다.

실용 팁: L2 정규화(벡터 길이를 1로 만들기)를 하면 ‖u‖=‖v‖=1이 되어 분모가 1이 되고, 코사인 유사도 = 내적(dot product)과 동일해진다. 그래서 임베딩 코드에서 normalize(X, norm="l2")를 먼저 하는 것이다.

1.6 임베딩의 활용 사례

  • 검색(Semantic Search): 키워드가 일치하지 않아도 의미가 비슷한 문서를 찾아준다. RAG(Retrieval-Augmented Generation)의 핵심.
  • 추천 시스템: 비슷한 사용자·아이템을 벡터 거리로 찾는다.
  • 분류·클러스터링: 라벨이 없어도 비슷한 것들끼리 묶을 수 있다.
  • 이상 탐지: 평소 분포에서 멀리 떨어진 벡터 = 이상치.
  • 다국어 정렬: multilingual 임베딩은 한국어 "기자"와 영어 "journalist"를 같은 공간의 가까운 점으로 표현한다.
  • 저널리즘 응용: 대량 보도자료 분류, 사설 입장 분석, 가짜뉴스 유사도 추적, 인터뷰 응답 클러스터링.

  • 영문 입문 실습: all-MiniLM-L6-v2.
  • 긴 한국어 문서(>512 토큰): bge-m3(8192 토큰까지 처리).

2.3 모델 선택의 일반 원칙

  1. 언어: 한국어 비중이 크면 다국어/한국어 특화 모델.
  2. 문서 길이: 평균 토큰 길이가 512를 넘으면 long-context 모델(BGE-M3, Gemini 등) 또는 청크 분할.
  3. 비용 vs 성능: API는 편하지만 대량 처리 시 비용 누적. 1만 건 이상이고 반복 사용한다면 오픈소스 + GPU/CPU 로컬이 결국 싸다.
  4. 재현성·프라이버시: 민감 데이터(인터뷰 응답, 미공개 보도자료)는 로컬 모델.
  5. 벤치마크: 한국어는 KLUE-STS, Ko-MTEB 등의 STS·Retrieval 점수를 참고.

3.3 배치 임베딩 (실전)

from google import genai
from google.genai import types
import numpy as np

client = genai.Client()

docs = [
    "한국 언론의 정파성에 관한 연구는 오랜 역사를 가진다.",
    "딥러닝 기반 자연어 처리 기술이 빠르게 발전하고 있다.",
    "제주도 부동산 시장은 지난해 큰 폭의 조정을 겪었다.",
    # ... 수천 개
]

# task_type 지정이 성능에 매우 중요: 목표별 다소 차이나게 학습됨
# - RETRIEVAL_DOCUMENT:  RAG 문서(벡터 DB) 저장

#  -  RETRIEVAL_QUERY: 사용자 검색
# - SEMANTIC_SIMILARITY: 유사도 비교
# - CLASSIFICATION: 분류용. 에를 들면 감성 분석, 주제 분류 등
# - CLUSTERING: 군집 분석, 토픽 탐색

embeddings = []
batch_size = 100
for i in range(0, len(docs), batch_size):
    batch = docs[i:i+batch_size]
    resp = client.models.embed_content(
        model="gemini-embedding-001",
        contents=batch,
        config=types.EmbedContentConfig(
            task_type="CLUSTERING",
            output_dimensionality=768,  # 3072 → 768로 축소도 가능(Matryoshka)
        ),
    )
    embeddings.extend([e.values for e in resp.embeddings])

X = np.array(embeddings)  # (N, 768)
print(X.shape)

중요 포인트

  • task_type을 지정하지 않으면 일반 임베딩이 나온다. 군집분석(클러스터링)에는 반드시 CLUSTERING 지정.
  • output_dimensionality로 차원을 줄이면 메모리·속도가 좋아진다(768 권장).

3.4 SBERT 로컬 모델 비교 예시

from sentence_transformers import SentenceTransformer

model = SentenceTransformer("intfloat/multilingual-e5-large")
# E5 계열은 "passage: " 접두사를 붙여야 최적 성능
docs_with_prefix = [f"passage: {d}" for d in docs]
X = model.encode(docs_with_prefix, normalize_embeddings=True, show_progress_bar=True)

4.1 임베딩 모델의 입력 길이 제한

multilingual-e5-large 512
BGE-M3 8192
Gemini Embedding 2048 (모델·버전마다 상이, 공식 문서 확인)

긴 기사·논문은 잘려서 뒷부분이 무시된다. 대응 방법은 세 가지다.

4.2 대응 전략

전략 A. 청크 분할 후 평균(pooling)

def chunk_text(text, chunk_size=400, overlap=50):
    words = text.split()
    chunks = []
    for i in range(0, len(words), chunk_size - overlap):
        chunks.append(" ".join(words[i:i+chunk_size]))
    return chunks

chunk_vecs = model.encode(chunks)
doc_vec = chunk_vecs.mean(axis=0)  # 단순 평균

장점: 정보 손실 적음. 단점: 평균이 의미를 흐릴 수 있음.

전략 B. LLM 요약 후 임베딩

긴 문서일수록 핵심 주제만 남기고 요약하는 것이 클러스터링 품질을 높인다. 특히 혼합 주제 문서(예: 정치+경제 혼합 사설)는 요약을 거치면 주된 입장이 분명해진다.

from google import genai
client = genai.Client()

def summarize(text, target_tokens=200):
    prompt = f"""다음 문서의 핵심 주제·주장·소재를 200자 이내로 요약하라. 
배경 설명, 인용, 부가 정보는 제외하고 본 문서의 정체성을 가장 잘 드러내는 부분만 남겨라.

문서:
{text}

요약:"""
    resp = client.models.generate_content(
        model="gemini-2.5-flash-lite",
        contents=prompt,
    )
    return resp.text.strip()

summaries = [summarize(d) for d in long_docs]
X = embed(summaries)

권장: 2000자 이상 문서는 요약 후 임베딩이 거의 항상 더 좋은 클러스터 결과를 낸다.

4.3 기타 전처리

  • HTML 태그·광고·내비게이션 텍스트 제거
  • 너무 짧은 문서(예: 50자 미만) 제외 또는 별도 처리
  • 중복 문서 제거(near-duplicate detection): MinHash 또는 임베딩 코사인 0.98 이상 묶기
  • 언어 감지·필터링: 다국어 코퍼스에서 한국어만 분석할 때

5. K-means 클러스터링

5.1 알고리즘

  1. K개의 중심점(centroid)을 임의로 배치
  2. 각 점을 가장 가까운 중심에 배정
  3. 각 클러스터의 평균으로 중심을 갱신
  4. 변화가 없을 때까지 2-3 반복

📏 임베딩 적용 시 거리 척도

일반 K-means는 유클리드 거리²(‖x − μk‖²)로 "가장 가까운 중심"을 판단한다. 그런데 임베딩 벡터에서 의미는 방향에 담겨 있고 벡터 크기(norm)는 의미와 무관하다. 그래서 그냥 쓰면 긴 문서·스케일 차이가 클러스터를 지배하는 문제가 생긴다.

해결책은 L2 정규화로 모든 벡터 길이를 1로 맞추는 것이다. 이 조건에서 다음 등식이 성립한다.

‖x − μk‖² = 2 − 2 · cos(x, μk)

거리 척도 사용 조건 의미
유클리드 거리²
‖x − μk‖²		 정규화 없이 벡터 크기 차이가 지배 → ❌ 의미 비교 부적합
유클리드 거리²
(L2 정규화 후)		 normalize(X, norm="l2") 후 코사인 유사도 최대화와 수학적으로 동치 → ✅
코사인 거리
1 − cos(x, μk)		 metric="cosine" 명시 방향 차이를 직접 측정 → ✅ (UMAP·실루엣에서 권장)

💡 결론: 임베딩 K-means에서는 normalize(X, norm="l2")를 먼저 적용하는 것이 수학적으로 필수다. 이후 WCSS의 유클리드 거리²를 최소화하는 것은 곧 코사인 유사도(의미적 유사도)를 최대화하는 것과 같다.

목적함수: 클러스터 내 분산(within-cluster sum of squares, WCSS) 최소화

WCSS = Σk=1K Σx ∈ Ck ‖x − μk‖²

기호 의미
K총 클러스터 수 (내가 지정하는 값)
Ckk번째 클러스터에 속한 점들의 집합
x클러스터 Ck 안에 있는 개별 데이터 포인트(문서 벡터)
μkk번째 클러스터의 중심점(centroid) — 클러스터 내 모든 벡터의 평균
‖x − μk‖²점 x와 중심 μk 사이의 거리²(유클리드 거리의 제곱)

💡 한 줄 해석: "모든 클러스터에서, 각 점과 자기 클러스터 중심 사이의 거리²를 다 더한 값"이 WCSS다. K-means는 이 값을 최소화하는 방향으로 학습하므로, 각 클러스터가 최대한 촘촘하게 뭉치도록 중심을 계속 업데이트한다. WCSS가 작을수록 클러스터 내 문서들이 서로 의미적으로 가깝다는 뜻이다.

5.2 임베딩에 K-means 적용 시 주의점

  1. 반드시 L2 정규화: 임베딩 벡터를 단위벡터로 만들면 유클리드 거리 ≈ 코사인 거리가 되어 의미 비교가 일관된다.
   from sklearn.preprocessing import normalize
   X_norm = normalize(X, norm="l2")
  1. 고차원 저주: 1024차원 이상이면 거리들이 비슷해져 K-means가 불안정. UMAP으로 30~50차원으로 축소 후 K-means 권장.
   import umap
   reducer = umap.UMAP(n_components=50, metric="cosine", random_state=42)
   X_reduced = reducer.fit_transform(X_norm)
  1. k-means++ 초기화: scikit-learn 기본값. 초기 중심 선택을 분산시켜 수렴 품질이 좋아진다.
  2. 여러 번 실행: n_init=10 이상으로 무작위성에 강건하게.

5.3 기본 코드

from sklearn.cluster import KMeans
from sklearn.preprocessing import normalize

X_norm = normalize(X, norm="l2")

km = KMeans(n_clusters=8, n_init=20, random_state=42)
labels = km.fit_predict(X_norm)

6. K 값 선택 방법

K(클러스터 수) 결정은 단일 정답이 없다. 여러 지표를 함께 보고, 연구 목적과 해석 가능성으로 최종 결정한다.

6.1 Elbow Method (엘보 법)

K를 늘려가며 WCSS(또는 inertia)를 플롯한다. 감소율이 급격히 꺾이는 "팔꿈치" 지점을 K로 선택.

import matplotlib.pyplot as plt
inertias = []
Ks = range(2, 21)
for k in Ks:
    km = KMeans(n_clusters=k, n_init=10, random_state=42).fit(X_norm)
    inertias.append(km.inertia_)
plt.plot(Ks, inertias, "o-")
plt.xlabel("K"); plt.ylabel("WCSS"); plt.show()

장점: 직관적. 단점: 꺾임이 모호할 때가 많음.

6.2 Silhouette Score (실루엣 점수)

각 점이 자기 클러스터에 얼마나 잘 맞고 다른 클러스터와는 얼마나 떨어졌는지 측정. -1~1, 높을수록 좋음.

s(i) = ( b(i) − a(i) ) ⁄ max( a(i), b(i) )

기호 의미 좋은 클러스터라면?
a(i)점 i와 같은 클러스터 내 다른 점들과의 평균 거리 (응집도)작을수록 좋음 — 같은 그룹이 촘촘
b(i)점 i와 가장 가까운 다른 클러스터 내 점들과의 평균 거리 (분리도)클수록 좋음 — 다른 그룹과 멀리 떨어짐
s(i)실루엣 점수 (범위: −1 ~ +1)+1에 가까울수록 이상적

💡 한 줄 해석: "내 그룹에 얼마나 잘 속하는가(b)에서 다른 그룹과 얼마나 섞이는가(a)를 뺀 것"이 분자다. b(i)가 a(i)보다 훨씬 크면(잘 분리됨) s(i)→+1, a(i)>b(i)이면(오분류 가능성) s(i)→음수가 된다.

해석 기준: s > 0.7 — 강한 구조 ｜ 0.5~0.7 — 적절 ｜ 0.25~0.5 — 약한 구조 ｜ < 0.25 — 클러스터링 재검토 

from sklearn.metrics import silhouette_score
for k in range(2, 21):
    km = KMeans(n_clusters=k, n_init=10, random_state=42).fit(X_norm)
    s = silhouette_score(X_norm, km.labels_, metric="cosine")
    print(k, s)

장점: 절대값 비교 가능. 단점: 데이터가 많으면 계산 느림(샘플링 사용).

6.3 Davies-Bouldin Index (DB 지수)

클러스터 내 분산 대비 클러스터 간 거리 비율. 낮을수록 좋음.

from sklearn.metrics import davies_bouldin_score
db = davies_bouldin_score(X_norm, labels)

6.4 Calinski-Harabasz Index (CH 지수)

클러스터 간 분산 / 클러스터 내 분산. 높을수록 좋음. 대용량에 빠름.

from sklearn.metrics import calinski_harabasz_score
ch = calinski_harabasz_score(X_norm, labels)

6.5 Gap Statistic (갭 통계량)

실제 데이터의 WCSS를 무작위 데이터의 WCSS와 비교해, 차이(gap)가 가장 큰 K를 선택. 통계적 근거가 강하지만 계산 비용이 크다.

6.6 BIC / AIC (GMM 사용 시)

K-means 대신 Gaussian Mixture Model을 쓰면 정보기준으로 K 선택 가능.

from sklearn.mixture import GaussianMixture
bics = [GaussianMixture(n_components=k, random_state=42).fit(X_norm).bic(X_norm) for k in range(2, 21)]

6.7 HDBSCAN: K를 정하지 않는 대안

밀도 기반 클러스터링. K를 미리 정할 필요가 없고, 클러스터에 속하지 않는 노이즈도 식별한다. 임베딩 + UMAP + HDBSCAN 조합은 BERTopic의 기반이며, 실제 연구에서 K-means보다 자연스러운 군집을 자주 만든다.

import hdbscan
clusterer = hdbscan.HDBSCAN(min_cluster_size=20, metric="euclidean")
labels = clusterer.fit_predict(X_reduced)  # -1은 노이즈

6.8 실전 권장: 다중 지표 + 도메인 해석

  1. K 후보 범위(예: 5~25)에서 Silhouette, DB, CH를 함께 계산.
  2. 상위 3~5개 K를 후보로 좁힘.
  3. 각 후보 K에 대해 클러스터별 대표 문서 10개씩 읽어 의미적으로 분리되는지 확인.
  4. 연구 가설·이론적 카테고리 수와 부합하는 K 채택.

**원칙**: 통계 지표는 후보를 좁히는 데 쓰고, 최종 결정은 **해석 가능성**으로 한다. 학술 논문에서도 이 정당화가 핵심이다.

7. 클러스터의 주제 도출 (Topic Naming)

7.1 전통적 방법: TF-IDF 키워드

📖 TF-IDF란? (Term Frequency – Inverse Document Frequency)

"이 단어가 이 문서에서 얼마나 자주 나오면서, 동시에 다른 문서에는 얼마나 드물게 등장하는가"를 수치로 나타낸 것이다. 흔한 단어(예: '이다', '있다', '한국')는 여러 문서에 다 나타나므로 낮은 점수를 받고, 특정 문서에만 집중적으로 등장하는 단어(예: '탄핵', '반도체 공급망')는 높은 점수를 받는다.

TF-IDF(t, d) = TF(t, d) × IDF(t)

구성요소 의미 높으면?
TF(t, d)단어 t가 문서 d에 등장하는 빈도그 문서에서 핵심 단어일 가능성
IDF(t)전체 문서 수 ÷ t가 등장하는 문서 수 (로그 적용)희귀한 단어일수록 구별력 높음

⚠️ 한계: "기자"와 "언론인"처럼 의미는 같지만 표현이 다른 단어는 점수를 공유하지 못한다. 또한 문맥·어순을 전혀 고려하지 않는다(Bag-of-Words). 이것이 임베딩 방식이 필요한 근본적 이유다. 클러스터 주제 도출에서는 보조적 수단으로만 활용한다.

각 클러스터 내 문서들의 TF-IDF 상위 단어로 주제를 추정. 빠르지만 단어 나열이라 해석에 노력이 든다.

from sklearn.feature_extraction.text import TfidfVectorizer

def top_words_per_cluster(docs, labels, top_n=10):
    result = {}
    for c in set(labels):
        cluster_docs = [d for d, l in zip(docs, labels) if l == c]
        tfidf = TfidfVectorizer(max_features=5000).fit_transform(cluster_docs)
        avg = tfidf.mean(axis=0).A1
        terms = TfidfVectorizer(max_features=5000).fit(cluster_docs).get_feature_names_out()
        top_idx = avg.argsort()[::-1][:top_n]
        result[c] = [terms[i] for i in top_idx]
    return result

c-TF-IDF (class-based TF-IDF, BERTopic 방식)는 한 클러스터를 하나의 거대 문서로 보고 TF-IDF를 계산해 클러스터 특이 단어를 더 잘 잡는다.

7.2 대표 문서 추출

각 클러스터에서 중심(centroid)에 가까운 문서 N개를 뽑으면, 이 문서들이 클러스터의 "전형"이다.

import numpy as np

def representative_docs(X_norm, labels, docs, n=5):
    reps = {}
    for c in set(labels):
        idx = np.where(labels == c)[0]
        center = X_norm[idx].mean(axis=0)
        dists = np.linalg.norm(X_norm[idx] - center, axis=1)
        top = idx[np.argsort(dists)[:n]]
        reps[c] = [docs[i] for i in top]
    return reps

7.3 LLM으로 주제 명명 (추천)

Gemini 등 LLM에 대표 문서 + 상위 키워드를 함께 던지고 주제명을 받는다.

def name_cluster(rep_docs, top_keywords):
    docs_str = "\n---\n".join(rep_docs)
    kw_str = ", ".join(top_keywords)
    prompt = f"""다음은 같은 클러스터로 분류된 문서들의 대표 샘플과 상위 키워드다.
이 클러스터의 공통 주제를 다음 형식으로 도출하라.

- 주제명(15자 이내):
- 주제 설명(2~3문장):
- 핵심 키워드 5개:

상위 키워드: {kw_str}

대표 문서:
{docs_str}
"""
    resp = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=prompt,
    )
    return resp.text

# 전체 적용
reps = representative_docs(X_norm, labels, docs, n=7)
top_kws = top_words_per_cluster(docs, labels, top_n=15)
topics = {c: name_cluster(reps[c], top_kws[c]) for c in set(labels)}

왜 LLM 주제명이 우수한가

  • 단어 나열이 아니라 개념적 명명을 한다 ("선거 보도, 후보자 비판, 부동산 정책" 같은 키워드 → "여당의 부동산 정책 실패를 둘러싼 선거 국면 비판").
  • 대표 문서의 실제 문맥을 읽고 주제를 잡으므로 단어 빈도로는 안 보이는 잠재 주제도 포착.
  • 일관된 명명 규칙(글자수, 형식)을 강제할 수 있다.
  • 다국어 문서도 통합 명명 가능.

7.4 클러스터 품질 검증

LLM에게 "이 대표 문서들이 한 주제로 묶이는 게 타당한가? 이질적인 문서가 있다면 지적하라" 같은 검증 프롬프트를 추가로 던지면 K 선택의 근거가 강해진다.

8. LDA·의미연결망 대비 SBERT+K-means의 우수성

8.1 LDA(Latent Dirichlet Allocation) 한계

LDA는 2003년에 제안된 확률 토픽모델로 오랜 시간 주류였다. 그러나 다음 한계가 명확하다.

항목 LDA SBERT + K-means
의미 단위 Bag-of-Words. 어순·문맥 무시 문장 구조·문맥 반영
다의어 처리 "사과(과일)"와 "사과(애플)" 구분 불가 문맥 임베딩으로 자연 분리
유사 표현 "기자"와 "언론인"이 별개 단어로 취급 같은 영역에 매핑
전처리 부담 불용어 사전, 어간 추출, 명사 추출 필수 (한국어는 형태소 분석기 의존) 모델이 raw text를 그대로 처리
하이퍼파라미터 α, β, K 모두 민감 K만 결정하면 됨
해석 가능성 토픽이 "단어 분포"로만 표현, 의미 해석은 연구자 몫 대표 문서 + LLM 주제명으로 즉시 해석 가능
소수 문서 클러스터 잘 안 잡힘 잘 잡힘
다국어 코퍼스 언어별로 별도 분석 필요 다국어 임베딩으로 통합 처리
사전학습 지식 없음. 코퍼스 통계만 사용 수십억 토큰의 사전학습 의미 지식 활용
외부 검증 perplexity, coherence 등 지표가 인간 판단과 약한 상관 코사인 유사도가 인간 의미 판단과 강한 상관

특히 한국어에서 LDA는 형태소 분석 품질에 크게 좌우되어 결과가 불안정하다. 임베딩은 형태소 분석 없이도 작동한다.

8.2 의미연결망(Semantic Network) 분석 한계

의미연결망은 단어 동시출현(co-occurrence)을 그래프 노드·엣지로 표현하는 방법이다.

항목 의미연결망 SBERT + K-means
분석 단위 단어. 문장·문서 단위 비교 어려움 문장·문서 단위 직접 비교
의미 vs 표면 단어 공출현(표면)만 본다 의미적 유사도 자체를 본다
그래프 해석 시각적으로 풍부하지만 정량 비교 어려움 거리·유사도가 정량 지표
확장성 노드·엣지 수가 폭증하면 해석 불가 수십만 문서도 처리 가능
시점 비교(종단) 그래프 비교 절차가 복잡 시점별 클러스터 변화 추적 용이
이론 친화성 어휘 중심, 프레임 분석에 적합 주제·입장·서사 분석에 적합

의미연결망이 무조건 열등한 것은 아니다. 언어의 표면 구조, 프레임 어휘, 사회적 키워드 관계를 보는 데는 여전히 유효하다. 그러나 문서·기사·인터뷰 응답의 의미 분류 문제에는 임베딩 접근이 더 정밀하다.

8.3 언제 어떤 방법을 쓸 것인가

연구 질문 추천 방법
"이 코퍼스에 어떤 주제가 있나" (탐색적) SBERT + K-means(또는 HDBSCAN) + LLM 주제명
"특정 단어가 어떤 단어들과 함께 쓰이나" 의미연결망 / 공출현 분석
"보도 프레임이 어떻게 구성되나" 의미연결망 + 질적 분석
"대규모 문서의 시계열 주제 변화" 임베딩 + 클러스터링 + 시점별 비교
"토픽 비중의 확률 모델이 필요" LDA, BTM, 또는 BERTopic

결론: 분류·검색·대규모 의미 분석에서는 임베딩 기반이 우월하다. 의미연결망과 LDA는 보조 분석 또는 다른 질문에 적합하다.

9. 전체 파이프라인 코드 (문서)

"""
End-to-end: 한국어 문서 클러스터링 + 주제 도출
"""
import numpy as np
import pandas as pd
from google import genai
from google.genai import types
from sklearn.preprocessing import normalize
from sklearn.cluster import KMeans
from sklearn.metrics import silhouette_score
import umap

client = genai.Client()

# 1. 데이터 로드
df = pd.read_csv("articles.csv")  # columns: id, title, text
docs = df["text"].tolist()

# 2. 긴 문서 요약
def maybe_summarize(text, threshold=2000):
    if len(text) < threshold:
        return text
    resp = client.models.generate_content(
        model="gemini-2.5-flash-lite",
        contents=f"다음 문서의 핵심 주제와 주장을 200자 이내로 요약하라.\n\n{text}",
    )
    return resp.text.strip()

docs_clean = [maybe_summarize(d) for d in docs]

# 3. 임베딩
def embed_batch(texts, batch_size=100):
    out = []
    for i in range(0, len(texts), batch_size):
        resp = client.models.embed_content(
            model="gemini-embedding-001",
            contents=texts[i:i+batch_size],
            config=types.EmbedContentConfig(
                task_type="CLUSTERING",
                output_dimensionality=768,
            ),
        )
        out.extend([e.values for e in resp.embeddings])
    return np.array(out)

X = embed_batch(docs_clean)
X = normalize(X, norm="l2")

# 4. 차원 축소
X_red = umap.UMAP(n_components=30, metric="cosine", random_state=42).fit_transform(X)

# 5. K 후보 평가
scores = {}
for k in range(5, 21):
    km = KMeans(n_clusters=k, n_init=10, random_state=42).fit(X_red)
    s = silhouette_score(X_red, km.labels_)
    scores[k] = s
    print(k, round(s, 4))

best_k = max(scores, key=scores.get)
print(f"Best K = {best_k}")

# 6. 최종 클러스터링
km = KMeans(n_clusters=best_k, n_init=20, random_state=42).fit(X_red)
df["cluster"] = km.labels_

# 7. 대표 문서 + 주제 명명
def representative_docs(X_red, labels, docs, n=7):
    reps = {}
    for c in set(labels):
        idx = np.where(labels == c)[0]
        center = X_red[idx].mean(axis=0)
        dists = np.linalg.norm(X_red[idx] - center, axis=1)
        top = idx[np.argsort(dists)[:n]]
        reps[c] = [docs[i] for i in top]
    return reps

reps = representative_docs(X_red, km.labels_, docs_clean)

def name_cluster(rep_docs):
    joined = "\n---\n".join(rep_docs)
    prompt = f"""다음은 같은 클러스터로 분류된 대표 문서들이다.
공통 주제를 아래 JSON 형식으로만 응답하라.

{{"topic_name": "15자 이내 주제명", "description": "2~3문장 설명", "keywords": ["단어1", "단어2", "단어3", "단어4", "단어5"]}}

문서:
{joined}
"""
    resp = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=prompt,
        config=types.GenerateContentConfig(response_mime_type="application/json"),
    )
    import json
    return json.loads(resp.text)

topics = {c: name_cluster(reps[c]) for c in set(km.labels_)}
for c, t in topics.items():
    n = (df["cluster"] == c).sum()
    print(f"[Cluster {c}] n={n} | {t['topic_name']}")
    print(f"  {t['description']}")
    print(f"  keywords: {', '.join(t['keywords'])}")

10. 이미지 분류: 같은 분석 틀의 확장

이미지에도 정확히 같은 파이프라인이 적용된다. CLIP(Contrastive Language-Image Pretraining)은 이미지와 텍스트를 같은 의미 좌표 공간(vector space)에 배치하도록 학습한 모델이다. 예를 들어 “고양이 사진”과 “a cat sitting on a sofa”라는 문장은 서로 가까운 벡터 위치로 이동하고, 반대로 “전투기 사진”과 “강아지 산책” 같은 관련 없는 조합은 멀어지도록 contrastive learning 방식으로 학습한다. 즉 CLIP은 이미지를 단순 픽셀로 보는 것이 아니라, “무엇을 의미하는 장면인가”를 언어 수준에서 이해하도록 만든 모델이다.

그래서 CLIP 이후에는:

- 텍스트로 이미지 검색

- 이미지로 유사 이미지 검색

- 이미지 자동 군집화(clustering)

- 이미지-기사 의미 불일치 탐지

같은 작업이 가능해졌다.이 이미지와 텍스트를 같은 의미 벡터 공간에 정렬해 서로 직접 검색·비교할 수 있게 만든 것이다.

이미지 → (전처리) → 이미지 임베딩 모델 → 벡터 → K-means → 대표 이미지 → 멀티모달 LLM 주제 도출

10.1 이미지 임베딩 모델

모델 특징
CLIP (OpenAI, 2021) 이미지-텍스트 공동 학습. 텍스트로 이미지를 검색할 수 있는 게 결정적 장점. ViT-B/32, ViT-L/14 등 변형 다수
OpenCLIP 오픈소스 재학습판, LAION 데이터로 학습. CLIP보다 강한 경우 많음
SigLIP / SigLIP2 (Google) CLIP 후속, sigmoid loss로 안정성·효율 개선
DINOv2 (Meta) 자기지도 학습 비전 모델. 의료·과학 등 도메인 특화 분류에 강함
EVA-CLIP, BLIP-2 더 큰 멀티모달 모델
Gemini Vision API로 이미지를 LLM에 직접 넣어 임베딩 또는 캡션 생성 가능

10.2 CLIP 기반 이미지 임베딩 코드

import torch
from PIL import Image
from transformers import CLIPProcessor, CLIPModel

device = "cuda" if torch.cuda.is_available() else "cpu"
model = CLIPModel.from_pretrained("openai/clip-vit-large-patch14").to(device).eval()
processor = CLIPProcessor.from_pretrained("openai/clip-vit-large-patch14")

def embed_images(paths, batch_size=32):
    vecs = []
    for i in range(0, len(paths), batch_size):
        imgs = [Image.open(p).convert("RGB") for p in paths[i:i+batch_size]]
        inputs = processor(images=imgs, return_tensors="pt").to(device)
        with torch.no_grad():
            v = model.get_image_features(**inputs)
        v = v / v.norm(dim=-1, keepdim=True)
        vecs.append(v.cpu().numpy())
    return np.concatenate(vecs)

10.5 클러스터 주제 도출: 멀티모달 LLM

이미지 클러스터의 주제는 대표 이미지 몇 장을 Gemini Vision에 직접 입력해 도출한다.

from google import genai
from pathlib import Path

client = genai.Client()

def representative_images(X_img, labels, paths, n=6):
    reps = {}
    for c in set(labels):
        idx = np.where(labels == c)[0]
        center = X_img[idx].mean(axis=0)
        dists = np.linalg.norm(X_img[idx] - center, axis=1)
        top = idx[np.argsort(dists)[:n]]
        reps[c] = [paths[i] for i in top]
    return reps

def name_image_cluster(image_paths):
    parts = []
    for p in image_paths:
        parts.append({"inline_data": {"mime_type": "image/jpeg", "data": Path(p).read_bytes()}})
    parts.append({"text": """위 이미지들은 같은 클러스터로 묶였다. 공통 시각적·주제적 특징을 도출하라.
JSON: {"topic_name": "15자 이내", "visual_features": "구도·색감·소재 등 시각 특징", "subject": "주제·맥락", "keywords": ["단어1","단어2","단어3","단어4","단어5"]}"""})
    resp = client.models.generate_content(
        model="gemini-2.5-flash",
        contents=[{"role": "user", "parts": parts}],
        config=types.GenerateContentConfig(response_mime_type="application/json"),
    )
    import json
    return json.loads(resp.text)

reps_img = representative_images(X_img, img_labels, image_paths)
image_topics = {c: name_image_cluster(reps_img[c]) for c in set(img_labels)}

10.6 텍스트-이미지 통합 분석

CLIP·SigLIP은 텍스트 인코더와 이미지 인코더의 출력을 같은 좌표 공간에 정렬되도록 학습한 모델이다. 인터넷에서 수집한 수억 쌍의 (이미지, 캡션)을 가지고, 올바른 쌍은 가까이, 잘못된 쌍은 멀리 놓이도록 두 인코더를 동시에 훈련(대조 학습, contrastive learning)한 결과다. 학습이 끝나면 "강아지 사진의 벡터"와 "a photo of a dog이라는 문장의 벡터"가 거의 같은 위치에 놓인다. 즉, 텍스트와 이미지를 같은 자(코사인 유사도)로 비교할 수 있다. 학습 데이터에 없던 카테고리도 작동하기 때문에 이를 제로샷(zero-shot) 능력이라 부른다.

10.7 응용 사례 (저널리즘·미디어)

  • 김정은 등 인물 시각 프레이밍 분석(국가별 매체 비교)
  • 광고·기사 이미지 구분
  • 유튜브 썸네일 클러스터링 → 채널 전략 분석
  • 딥페이크·합성 이미지 후보군 사전 선별

11. 강의 정리

  1. 임베딩은 비정형 데이터를 의미 좌표로 바꾸는 것이다. 이 좌표 위에서 거리는 곧 의미 차이다.
  2. SBERT 계열은 코사인 유사도가 의미 유사도와 일치하도록 학습된 문장 임베딩이다.
  3. 한국어에는 multilingual-e5-large, bge-m3, 또는 Gemini Embedding API(task_type="CLUSTERING")가 강력하다.
  4. 긴 문서는 LLM 요약 후 임베딩이 클러스터 품질을 높인다.
  5. K-means 적용 전 L2 정규화 + UMAP 차원 축소가 권장된다. K 선택은 Silhouette·DB·CH 등 다중 지표로 후보를 좁히고, 대표 문서 검토와 해석 가능성으로 최종 결정한다.
  6. 클러스터 주제명은 LLM에 대표 문서를 보여주고 도출하면 단순 키워드 나열보다 훨씬 풍부하다.
  7. LDA·의미연결망 대비 SBERT+K-means+LLM 파이프라인은 의미 표현력, 다국어, 전처리 부담, 해석 가능성 모두에서 우위다.
  8. 이미지에도 동일한 사고 틀이 적용된다. CLIP/SigLIP/DINOv2로 임베딩, 동일한 K-means, 멀티모달 LLM으로 주제명. 더 나아가 텍스트-이미지 통합 공간을 활용한 제로샷 분류도 가능하다.
